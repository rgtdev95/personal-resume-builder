# Project Information

Everything that isn't code lives here. This folder is the project's
memory - for you, your collaborators, and any AI assistant working on it.

## Files and folders

### README.md (this file)
Index of this folder - explains what each file and subfolder is for, so
nobody has to guess where something belongs.

### context.md
The single most important file here: a living snapshot of what this
project is, its current status, and its conventions. Read this first,
before any code or notes. When something here goes stale, rewrite it -
don't let it drift from reality.

### features.md
What each tab/feature does and the day-to-day workflow for using the app.
Product-facing documentation - what it does, not how it's built.

### architecture.md
Tech stack, project structure, database schema, and API reference - the
technical "what and how" of the codebase. Kept separate from decisions/
below: this describes the current shape of things, decisions/ explains why
it ended up that way.

### decisions/
One file per significant decision, named `YYYY-MM-DD-title.md`. Captures
*why* a choice was made - the alternatives considered and the reasoning -
not just what was chosen, so nobody re-litigates a settled question
without knowing why it was settled that way.

### notes/
Running journal, dated `YYYY-MM-DD-topic.md`. Day-to-day thinking,
progress, half-formed ideas. Lower stakes than decisions/, higher signal
than nothing.

### research/
External references: papers, articles, links, findings from outside the
project. Save a quote or summary alongside the source, not just a bare
link - links rot, summaries don't.

### archive/
Done or abandoned material, moved out of the active folders so current
work stays easy to scan. Nothing here is deleted, it's just out of the way.
